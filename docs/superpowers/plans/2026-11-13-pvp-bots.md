# PvP Bots Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Paper plugin that automatically spawns hidden, player-like fake-player bots: a personal 1v1 PvP trainer for each player in a WorldGuard training arena, and a fixed-size ally squad in WorldGuard boss areas, on Minecraft 1.21.11 → 26.2 from one jar.

**Architecture:** Pure Kotlin logic (difficulty, aim, pathfinding, brains, session state machines, slot cap) lives in `core` with no Bukkit types, so it is unit-tested with JUnit. Thin Bukkit/WorldGuard glue in `core` wires that logic to the server. All version-specific code (creating fake `ServerPlayer`s and driving them by inputs so vanilla runs their physics) sits behind the `BotAdapter` interface, one module per Minecraft version, chosen at startup.

**Tech Stack:** Kotlin 2.x targeting JVM 21 (all modules), Gradle Kotlin DSL multi-project, paperweight-userdev (adapters), Shadow (fat jar), run-paper (dev servers), WorldGuard 7 API, JUnit 5 + kotlin.test.

**Spec:** `docs/superpowers/specs/2026-11-12-pvp-bots-design.md`

## Global Constraints

- Supported Minecraft versions: **1.21.11, 26.1.x, 26.2.x** — one jar; any other version → log supported list and disable.
- **Language: Kotlin** in every module. `core` and `adapter-api` use `jvmTarget = 21` (Kotlin) and `--release 21` (any Java interop). Adapters may target the JDK their Minecraft version requires; they are loaded reflectively only on matching servers.
- **Kotlin stdlib is not bundled:** `plugin.yml` has `libraries: [org.jetbrains.kotlin:kotlin-stdlib:<kotlin version>]` (same version as the Gradle Kotlin plugin, from `libs.versions.toml`); Shadow excludes `kotlin-stdlib`. No coroutines.
- Bukkit/Paper API only in `core`; Minecraft internals (NMS) only in `adapter-*` modules.
- WorldGuard is a hard dependency (`depend: [WorldGuard]`).
- WorldGuard flag names exactly: `pvpbot-role` (`trainer`|`ally`), `pvpbot-difficulty` (`easy`|`medium`|`hard`|`pro`, default `medium`), `pvpbot-count` (int, default `5`, clamped to `1..max-bots`).
- Config defaults: `max-bots: 100`, trainer countdown **3 s**, time limit **300 s**, rematch delay **5 s**; ally respawn **15 s**, leave grace **10 s**; bot view & simulation distance **2**; stuck: retry at **5 s**, teleport at **10 s**.
- Melee reach **3.0** blocks; allies "peel" a hostile attacking a player within **4** blocks; ally bow when target is more than **4** blocks above.
- Player-facing text exactly: action bar `All trainers busy, please wait…`; title `You won!`; title `Trainer won`; title `Time's up — draw` (plan's choice; spec left it open).
- Bots: never saved to disk, never in the tab list, no join/quit/death messages, no drops/XP. Names `Trainer_xxxx` / `Ally_xxxx` (4 random lowercase hex digits), random UUID per spawn.
- Players never control bots. Admin commands only: `/pvpbots status|reload|clear` (permission `pvpbots.admin`), `/pvpbots selftest ...` (permission `pvpbots.debug`, test aid).
- Performance budget: all bot work ≤ **10 ms per tick** with **100** bots.
- Package root: `pvpbots`. Spec §12 open questions were approved with the spec's defaults (allies respawn, allies use bows, win/loss titles shown, sketch kits, 100-bot target).

### Spec conflict resolved here

Spec §7.5 gives hard/pro both "shield" and "totem in offhand"; only one item fits the offhand. Decision: the **shield** lives in the offhand; the **totem** lives in hotbar slot 8; at ≤ 25 % health a hard/pro bot swaps the totem into the offhand (and stops shielding). This is realistic "totem swap" play.

## Review Focus

1. **A player leaves, teleports/pearls out, disconnects or dies while QUEUED or in COUNTDOWN** → the queue entry or bot is removed at once, nobody else's slot is blocked. Test: Task 8 `ownerLeftWhileQueued_cancelsSlotRequest`, `ownerDiedDuringCountdown_removesBot`.
2. **Overlapping flagged regions** (an arena inside a boss area) → only the highest-priority flagged region applies. Test: Task 9 `overlap_highestPriorityFlaggedRegionWins`.
3. **Bots (which are Players to WorldGuard) walking into flagged regions** → never start sessions. Test: Task 9 `botEnteringArena_startsNothing`.
4. **Out-of-range / missing flag values** (`pvpbot-count 0`, `99999`, no difficulty) → clamped/defaulted, never crash. Test: Task 9 `count_clampedToOneAndMaxBots`, `missingDifficulty_defaultsToMedium`.
5. **`/pvpbots reload`, `clear`, or plugin disable with live fights and a queue** → every bot removed, queue emptied, no stale session later spawns a bot. Test: Task 9 `shutdown_removesAllBotsAndClearsQueue`; Task 3 `clear_emptiesQueueAndReleasesAll`.

## Shared Interfaces (defined once, used by many tasks)

```kotlin

    fun setInput(bot: BotHandle, input: BotInput)                  // applied during the bot's own vanilla tick
    fun attack(bot: BotHandle, target: org.bukkit.entity.Entity)
    fun swing(bot: BotHandle)
    fun startUsing(bot: BotHandle, hand: org.bukkit.inventory.EquipmentSlot)
    fun stopUsing(bot: BotHandle)
    fun selectSlot(bot: BotHandle, slot: Int)
    fun swapHands(bot: BotHandle)
}

// core.math (Task 4)
data class Vec3(val x: Double, val y: Double, val z: Double)  // plus, minus, times(Double), length(), horizontalDistance(), normalize()
data class Aabb(val min: Vec3, val max: Vec3)
data class Rotation(val yaw: Float, val pitch: Float)        // Minecraft convention: yaw 0 = +Z, 90 = -X; pitch -90 = up
data class BlockPos(val x: Int, val y: Int, val z: Int)
data class Bounds(val min: BlockPos, val max: BlockPos)      // inclusive; contains(BlockPos), contains(Vec3), clamp(Vec3)

// core.session (Task 3 declares SessionKey; Task 8 the rest)

    data class Trainer(val owner: UUID) : SessionKey
    data class Squad(val world: String, val regionId: String) : SessionKey

sealed interface Effect {
    data class RequestSlots(val key: SessionKey, val n: Int) : Effect
    data class CancelSlotRequests(val key: SessionKey) : Effect

    data class RemoveBot(val botId: UUID) : Effect

}
interface BotPort  // implemented by BotManager; used by AreaDirector — full signature in Task 9
```

### Reading the signatures and tests in this plan (Kotlin conventions)

Task signatures are written compactly as `Name.fn(Type arg, …): Return` and test snippets in a terse JUnit style. Implement and write them in **idiomatic Kotlin** using these exact mappings:

| Plan says | Write in Kotlin |
|---|---|
| `record X(...)` | `data class X(val ...)` |
| class with only static-style calls (`Aim`, `FairHit`, `Ballistics`, `InputMapper`, `AdapterLoader`, `ProfileLoader`, `Pathfinder`, `SpawnPointFinder`, `TargetSelector`, `DamagePolicy`, `TrainerBrain`, `AllyBrain`, `AreaResolver`, `PvpBotsApi`) | `object X` |
| `/*nullable*/` field | `T?` |
| `Optional<T>` / `OptionalDouble` | `T?` / `Double?` (tests: `assertEquals(expected, actual)` / `assertNull(...)`) |
| `List<…>`, `Map<…>`, `Set<…>` return | read-only Kotlin `List`/`Map`/`Set` |
| `RandomGenerator rng` | `kotlin.random.Random` |
| sealed interface with nested `record`s | sealed interface with nested `data class`es (as in Shared Interfaces) |
| test builders like `percept().health(0.3).hasFood(true).build()` | a test helper `fun percept(health: Double = 1.0, hasFood: Boolean = false, …): Perception` with named default arguments |
| test names `fooBar_baz()` | keep the name (backtick names optional) |

Tests use JUnit 5 + `kotlin.test` assertions. No coroutines anywhere.

### Task 5: Difficulty profiles and config loading

**Files:** Create `core/src/main/kotlin/pvpbots/profile/{Difficulty,CritMode,StrafeMode,ShieldMode,DifficultyProfile,ProfileLoader}.kt`, `core/src/main/resources/config.yml`; Test `core/src/test/kotlin/pvpbots/profile/ProfileLoaderTest.kt`

**Interfaces:**
- Produces:
  - `enum Difficulty { EASY, MEDIUM, HARD, PRO }`
  - `enum CritMode { NEVER(0), SOMETIMES(0.3), OFTEN(0.7), ALWAYS(1.0) }` with `double chance()`
  - `enum StrafeMode { NONE, SIMPLE, FULL, RANDOMISED }`; `enum ShieldMode { NONE, BASIC, FULL, FULL_AXE }`

**Trainer decision order** (first match wins; spec §7.2 + conflict resolution above):
1. `totem && health ≤ 0.25 && !offhandIsTotem && hasTotemInHotbar` → `heldSlot != TOTEM` ? select TOTEM : `SWAP_TOTEM`.
2. `healAt > 0 && health ≤ healAt && hasFood` → style RETREAT, select FOOD, `EAT` (continue EAT while `usingItem`).
3. Target blocking, shield mode `FULL_AXE`, `hasAxe`, `lookHitsTarget` → if `heldSlot != AXE` select AXE (action NONE) else `ATTACK`.
4. Not blocking target and `heldSlot != SWORD` → select SWORD.
5. `lookHitsTarget && cooldown ≥ threshold` → crit roll (`crits.chance()`): if crit and `onGround` → `jump=true`, action NONE, mark crit pending; if crit pending and `!onGround && velocity.y < 0` → `ATTACK`; no crit → `ATTACK`. After any ATTACK: resample threshold in `[cooldownMin, cooldownMax]`; if `wTap` set 2 ticks of `WTAP_RELEASE`.
6. Shield: `FULL`/`FULL_AXE` and target within 3.5 and cooldown < threshold and `hasShield` → `RAISE_SHIELD`; `BASIC` → same but only when cooldown < 0.5.
7. Movement: distance > 3.5 → `APPROACH_SPRINT`; else strafe per mode — NONE → WALK toward target; SIMPLE → flip direction every 40 ticks; FULL → every 20; RANDOMISED → every 8–30 ticks (random).
`lookAt` is always the target's chest (`box` centre). Trainer never selects BOW.

**Ally differences:** no step 3; no target → `WALK` to `followPos` if > 4 blocks away else STAND; target not reachable (`!targetReachable` or target more than 4 blocks above) and `hasBow` → select BOW, `DRAW_BOW` for 20 ticks, then `RELEASE_BOW` with `bowPitch` from `Ballistics.pitchFor(eye, target chest, 3.0)` (no shot if empty → WALK toward target).

**DamagePolicy rules:** Trainer↔its owner: allow. Trainer↔anything else (players, bots, mobs): deny. Ally→RealPlayer/Ally/Trainer: deny. RealPlayer→Ally: deny. Mob→Ally and Ally→Mob: allow. Everything else: allow.

  - `PvpBotsApi.isBot(org.bukkit.entity.Player): boolean`, `PvpBotsApi.bots(): Collection<org.bukkit.entity.Player>` (static, available after enable).

  - `BotController.tick(long tick)` — every server tick: refresh target fields of `Perception` every `reactionTicks` (self fields every tick); pick target (trainer: owner; ally: `TargetSelector` over Bukkit `Enemy` entities inside `area.bounds`); call brain (or STAND while not `director.fighting(botId)`); path via `Pathfinder` (recompute every 10 ticks or when goal moved > 2 blocks); `InputMapper` → `BotInput` (+ jump when next waypoint is higher and on ground); aim = `Aim.turnToward(look, Aim.withError(Aim.lookAt(eye, lookAt), aimError), turnSpeed)`; ATTACK only if `FairHit.hits(...)` with reach 3.0; allies outside bounds → move target `bounds.clamp(pos)`; `StuckDetector` RETRY → jump + new path, TELEPORT → nearest standable point near goal (inside bounds).
