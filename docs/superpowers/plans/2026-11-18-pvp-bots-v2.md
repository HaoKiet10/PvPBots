# PvP Bots v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend the working v1 plugin with Minecraft 26.3 support, arenas the plugin builds and removes itself (optionally with a fixed kit both sides fight in), and a hidden per-player skill rating that tunes the trainer to each player.

**Architecture:** Same split as v1: pure Kotlin logic (arena layout, block snapshots, inventory stash format, skill blending/judging/updating) in `core` with no Bukkit types, unit-tested with JUnit; thin Bukkit/WorldGuard glue in `core/bukkit`; version internals only in `adapter-*`. Adaptive skill rides the existing spawn path (`Effect.SpawnBot` → `BotPort.spawn` → `BotManager`) with a nullable difficulty meaning "adaptive".

**Tech Stack:** Kotlin 2.x (core/adapter-api JVM 21, 26.x adapters JVM 25), Gradle Kotlin DSL, paperweight-userdev, Shadow, run-paper, WorldGuard 7 / WorldEdit 7 API, JUnit 5 + kotlin.test.

**Spec:** `docs/superpowers/specs/2026-11-18-pvp-bots-v2-design.md` (on top of `docs/superpowers/specs/2026-11-12-pvp-bots-design.md`; v1 plan `docs/superpowers/plans/2026-11-13-pvp-bots.md` describes the existing code).

## Global Constraints

- All v1 Global Constraints still hold (Kotlin everywhere, stdlib not bundled, NMS only in adapters, no player commands, bots never saved, ≤ 10 ms/tick for 100 bots), except where listed below.
- Supported versions: **1.21.11, 26.1.x, 26.2.x, 26.3.x**, one jar; anything else refused with the supported list.
- `pvpbot-difficulty` **unset on a trainer region = adaptive** (v1: medium). Unset on an ally region stays **medium**.
- Skill rating range **0..100**; anchors easy **0**, medium **33**, hard **67**, pro **100**; discrete settings and kit switch to the higher anchor only within **5** of it; default start rating **50**.
- In-fight: adjust every **5 s**, step **3**, dead zone **±0.15** health lead, target lead **0.05**, damage-share tie-break outside **0.2..0.8**, max shift **15** per fight. Only number settings move mid-fight (reaction ticks, aim error, turn speed, cooldown min/max, heal-at).
- After fight: `new = old + 0.3 × (fightEnd − old)`, then **+4** player won / **−2** bot won / **0** draw, clamp 0..100. Player death from **any cause** during FIGHTING = bot won. Leave / bot failure / arena removed / clear = no change.
- Rating stored in the player's `PersistentDataContainer`, key **`pvpbots:skill`** (double). One rating per player.
- Real players **may** damage each other in trainer arenas (v1 `DamagePolicy` unchanged).
- Arena presets: `duel` 1 pad/side 17×17, `squad` 3 pads/side 25×25, `team` 5 pads/side 33×33 (inside floor); walls 5 high; open roof; interior cleared to wall height + 3; 3-wide entrance.
- Arena region id **`pvpbots_<name>`**, priority **10**, flags `pvpbot-role trainer`, `build deny`, `pvp allow`, no `pvpbot-difficulty`.
- Files: `plugins/PvpBots/arenas.yml`, `plugins/PvpBots/arenas/<name>.snapshot`, `plugins/PvpBots/stash/<uuid>.dat`. Snapshot and stash are written and flushed **before** any block or inventory change.
- `arenas.blocks-per-tick` default **4000**.
- Admin commands (permission `pvpbots.admin`): `/pvpbots arena create <name> <duel|squad|team> [kit] [confirm]`, `/pvpbots arena remove <name> [confirm]`, `/pvpbots arena list`, `/pvpbots arena kit <name> <kit|none>`.
- Kit arenas exist only for plugin-built arenas.

## Review Focus

1. **Server stops or crashes mid-build or mid-removal** → on next start the job finishes from the snapshot; no arena is half-built with fights in it, no terrain is lost. Test: Task 5 `job_resumedRemoving_restoresAllBlocks`, `job_resumedBuilding_completesLayout`.
2. **A player enters a kit arena while a stash file for them already exists** (re-entry after `/pvpbots reload`, crash then rejoin inside the arena) → the existing stash is never overwritten; it is restored first. Test: Task 6 `enter_withExistingStash_restoresBeforeStashing`.
3. **Items with rich data** (enchanted, renamed, damaged, shulker box full of items, written book) **survive stash → restore exactly.** Test: Task 6 self-test K1 compares `ItemStack.serializeAsBytes()` before/after per slot.
4. **Corrupt or out-of-range stored rating** (−20, 500, NaN, wrong PDC type) → clamped or defaulted to 50, never a crash. Test: Task 2 `rating_outOfRangeOrNaN_clampedOrDefaulted`.
5. **Arena create at the world border, above build height, over another arena or over a chest** → refused, nothing changed. Test: Task 3 `check_refusesOutsideHeight`, `check_refusesOverlap`; Task 5 self-test A4 (chest).

## Shared Interfaces (defined once, used by many tasks)

```kotlin
// skill (Task 2)
data class SkillSettings(val startRating: Double = 50.0, val adjustEverySeconds: Int = 5, val step: Double = 3.0,
    val deadZone: Double = 0.15, val targetLead: Double = 0.05, val maxShiftPerFight: Double = 15.0,
    val learnRate: Double = 0.3, val winBonus: Double = 4.0, val lossPenalty: Double = 2.0)
enum class Outcome { PLAYER_WON, BOT_WON, DRAW, NO_RESULT }
object SkillBlender {
    val ANCHORS: Map<Difficulty, Double>   // EASY 0, MEDIUM 33, HARD 67, PRO 100
    /** Full profile at the start of a fight; kitOverride replaces the blended kit (kit arenas). */
    fun startProfile(rating: Double, anchors: Map<Difficulty, DifficultyProfile>, kitOverride: String?): DifficultyProfile
    /** [base] with only the number settings replaced by the blend at [rating]. */
    fun retune(base: DifficultyProfile, rating: Double, anchors: Map<Difficulty, DifficultyProfile>): DifficultyProfile
    fun sanitize(stored: Double?, s: SkillSettings): Double   // null/NaN -> start, else clamp 0..100
}
data class Window(val playerHealthFrac: Double, val botHealthFrac: Double, val dealtToBot: Double, val takenByPlayer: Double)
object FightJudge { fun next(current: Double, start: Double, w: Window, s: SkillSettings): Double }
object RatingUpdate { fun after(old: Double, fightEnd: Double, outcome: Outcome, s: SkillSettings): Double }

// session (Task 2): difficulty == null means adaptive (trainers) / medium (allies)
data class AreaRef(world, regionId, role, val difficulty: Difficulty?, count, bounds, val arena: String? = null, val kit: String? = null)
Effect.SpawnBot(key, role, difficulty: Difficulty?, nearPlayer)
Effect.RoundEnded(val owner: UUID, val outcome: Outcome)
BotPort.spawn(key, role, difficulty: Difficulty?, area, nearPlayer): UUID?
BotPort.roundEnded(owner: UUID, outcome: Outcome) {}           // default no-op

// arena (Tasks 3-5)
enum class Preset(val padsPerSide: Int, val inside: Int) { DUEL(1, 17), SQUAD(3, 25), TEAM(5, 33) }
enum class Facing { NORTH, EAST, SOUTH, WEST }                  // from the admin's yaw
enum class Part { FLOOR, WALL, LIGHT, PAD_A, PAD_B, COVER, AIR }
data class Layout(val blocks: Map<BlockPos, Part>, val outer: Bounds, val region: Bounds,
                  val padsA: List<BlockPos>, val padsB: List<BlockPos>)   // pads = floor block under the spawn
object ArenaLayout { const val WALL_HEIGHT = 5; const val CLEAR_ABOVE = 3
    fun generate(preset: Preset, origin: BlockPos, facing: Facing): Layout }   // origin = block the admin stands on (floor level)
data class ArenaRecord(val name: String, val world: String, val origin: BlockPos, val facing: Facing, val preset: Preset,
    val regionId: String, val status: Status, val kit: String?, val padsA: List<BlockPos>, val padsB: List<BlockPos>) {
    enum class Status { BUILDING, READY, REMOVING } }
interface BlockWriter { fun read(p: BlockPos): String; fun write(p: BlockPos, blockData: String) }   // block data strings
object BlockSnapshot { fun encode(blocks: List<Pair<BlockPos, String>>): ByteArray; fun decode(b: ByteArray): List<Pair<BlockPos, String>> }
class ArenaJob(val targets: List<Pair<BlockPos, String>>, var done: Int = 0) { fun step(w: BlockWriter, budget: Int): Boolean } // true when finished
object StashCodec { fun encode(slots: List<ByteArray?>): ByteArray; fun decode(b: ByteArray): List<ByteArray?> }  // per-slot item bytes, null = empty
```
